# 计划：转发命令像真实 shell 一样保持状态，路径换算更准确

## 现状和问题

Claude 的每条 Bash 命令由钩子改写成 `pcrun '<命令>'`，每次新开一个 ssh 连接，到电脑的 Git Bash 里执行。

1. **慢**：每条命令都要重新建立 ssh 连接，实测约 1.15 秒，其中大部分是握手时间。
2. **不保留状态**：上一条命令里的 `cd`、`export`、`source .venv/Scripts/activate`、定义的函数和别名，下一条命令都没有了。
3. **路径换算太简单**：
   - 只认命令里写死的挂载路径（`~/work/pc-code/...` 等）。在 `~/work` 下写相对路径 `cd pc-code/proj` 不会被识别为要转发。
   - 字符串前缀匹配，`~/work/pc-code-old` 也会被当成挂载目录。
   - 电脑上输出的路径是 `/d/Code/proj/a.py` 或 `D:\Code\proj\a.py`，Claude 要自己换算成 `~/work/pc-code/proj/a.py` 才能用读、改文件的工具打开。
   - 命令里引用了只在 VPS 上存在的文件（比如 VPS 上的临时目录 `/tmp/...`），转发到电脑后找不到，报错也看不出原因。

## 方案选择

### 方案 A（推荐）：复用连接 + 保存会话状态

- **复用连接**：用 OpenSSH 的连接复用（ControlMaster），所有命令共用一条长期保持的 ssh 连接。实测第二条命令起每条约 0.26 秒，主要是 Windows 上启动 bash 的时间。
- **保存会话状态**：每条命令执行完，把当前目录、环境变量、函数、别名、shell 选项保存到电脑上的状态文件；下一条命令开始前先恢复。按 Claude 会话分开保存，不同会话互不影响。
- 这就是 Claude Code 在本机执行命令时用的做法：它也是每条命令启动一个新 shell，再恢复环境。

优点：
- 并行命令、后台命令（`run_in_background`）、超时中断都和现在一样能正常工作。
- 一条命令卡住，不影响其他命令。
- 改动集中在 `pcrun`，出问题容易回退。

不足：
- 不保留后台作业（`cmd &` 之后的 `jobs`、`fg`）和 shell 里正在运行的进程。
- 每条命令约 0.26 秒，比真正常驻的 shell 慢。

### 方案 B：真正常驻一个 shell 进程

在电脑上常驻一个 bash，每条命令写进它的标准输入，用特殊的结束标记切分输出和退出码。

优点：每条命令约 0.03 秒；后台作业等状态全部保留。

不足：
- 同一时间只能执行一条命令。Claude 并行执行多条命令、或有后台命令在跑时，需要再开 shell 或者排队。
- 命令超时被中断时，要能可靠地结束电脑上那条命令，同时不能把整个 shell 结束掉，在 Windows 上不好做。
- 某条命令把 shell 搞坏了（比如 `exec`、`exit`、改了 `IFS`），后面所有命令都受影响，要能检测并重建。
- 要在 VPS 上另外常驻一个管理进程。

## 方案 A 的具体做法

### 1. 复用连接
- `pcrun` 的 ssh 加上 `ControlMaster=auto`、`ControlPersist=10m`，控制文件放在 `~/.cache/claude-pc-bridge/`。
- 隧道断开后，复用的连接会失效。`pcrun` 检测到连接失败时，删掉旧的控制文件并重试一次。

### 2. 会话状态
- 钩子从 Claude Code 传入的信息里取会话 ID，传给 `pcrun`。
- 在电脑上执行时，把用户命令包在一段固定的开头和结尾里：
  - 开头：恢复状态文件（`~/.cache/claude-pc-bridge/sessions/<会话ID>.sh`）。
  - 结尾：用 `export -p`、`declare -f`、`alias -p`、`shopt -p` 把状态写回文件，记下当前目录，再返回用户命令的退出码。
- 要排除的环境变量：每次连接都会变的（`SSH_*`、`PWD`、`OLDPWD`、`SHLVL`、`_`），避免把上一次连接的值带过来。
- 状态文件 7 天没用自动删除。

### 3. 当前目录
- 当前目录以哪边为准：
  - Claude 这边的工作目录变了（比如用户执行了 `/cd`），就用 Claude 的目录换算成电脑上的路径。
  - Claude 的目录没变，就用电脑上一次保存的目录。这样电脑上 `cd` 到别的项目，下一条命令还在那里。
- 电脑上 `cd` 到挂载目录内的另一个位置时，同步改 Claude 这边的工作目录，让钩子和读、改文件工具的相对路径都跟上。做法是改写后的命令在 `pcrun` 结束后，在 VPS 上 `cd` 到对应的挂载路径，Claude Code 会记住这个目录。具体是否可行要先实测：Claude Code 只在命令成功、而且目录在允许的工作目录范围内时才会记住。

### 4. 路径换算
- **按路径边界匹配**：只有挂载路径后面紧跟 `/`、空白、引号或者字符串结尾时才算，`pc-code-old` 不再误判。
- **识别相对路径**：把命令按 shell 规则拆成一个个参数，逐个按 Claude 当前目录解析；解析后落在挂载目录里的，也触发转发，并换成电脑上的绝对路径。
- **输出路径反向换算**：电脑上输出的 `/d/Code/...`、`D:\Code\...`、`D:/Code/...` 换成 VPS 上的 `~/work/pc-code/...` 绝对路径，Claude 可以直接拿去读、改文件。只换这几个固定前缀（盘符不区分大小写），反斜杠一并换成 `/`。可以用 `PC_BRIDGE_RAW_OUTPUT=1` 关掉。
- **提示只在 VPS 上存在的路径**：转发的命令里有 VPS 上存在、但不在挂载目录里的绝对路径（如 `/tmp/...`、`/home/...`）时，在输出开头加一行提示：这个路径在电脑上不存在，要么把文件放到挂载目录里，要么在命令前加 `#local` 留在 VPS 上执行。

### 5. 测试
- 现有 `test/test.sh` 补充：路径边界、相对路径、输出反向换算、VPS 本地路径提示、会话状态的保存和恢复（用 `PC_BRIDGE_DRY_RUN` 和本机 bash 模拟，不连电脑）。
- 在电脑上实测：`cd`、`export`、激活 Python 虚拟环境、定义函数后，下一条命令都还在；并行执行两条命令；后台命令；超时中断；隧道断开再恢复后复用连接能自动重建。
- 记录每条命令的耗时，和现在的 1.15 秒对比。

## 决定

- 用方案 A。
- 输出路径反向换算默认开启，`PC_BRIDGE_RAW_OUTPUT=1` 关闭。
- 实测每条命令约 0.3 秒（原来约 1.2 秒）。为了这个速度，电脑上恢复和保存状态只用 bash 内置命令：Git Bash 里每启动一个外部程序要几十毫秒。
